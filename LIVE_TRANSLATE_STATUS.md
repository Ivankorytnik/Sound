# Speech Lab — Live EN → RU (экспериментальная версия, 23.11.2026)

## Цель
Бесплатный перевод английской речи во время совещания в веб-версии Контур.Толка.
Видео остаётся в Толке; `live-translate.html` показывает беззвучный предпросмотр вкладки
и переводимые субтитры. Функция изолирована от существующего `video.html`/видеозаписи.

## Использование
1. Открыть Контур.Толк в Chrome/Edge на ПК.
2. На странице «Видео в текст» выбрать «Живой перевод».
3. Нажать «Подготовить модели». На первом запуске дождаться полной загрузки
   Whisper Tiny и Xenova OPUS-MT EN→RU; потребуется сеть, кэш и свободная память.
4. Нажать «Начать перевод» и в системном диалоге выбрать вкладку Толка
   с опцией «Также передавать аудио вкладки». Без аудиотрека запуск блокируется.
5. Получать EN/RU в протоколе; при необходимости открыть окно субтитров.
6. Остановить захват, скачать TXT/SRT. Записи звука/видео этот режим не делает.

## Реализация
- Захват с явного пользовательского разрешения: `getDisplayMedia`.
- Web Audio -> 16 кГц моно -> фиксированные ~6-секундные фрагменты.
- Отдельный Web Worker: локальный Whisper Tiny, затем `Xenova/opus-mt-en-ru`
  через Transformers.js 3.8.1.
- Ограниченная очередь: один фрагмент в обработке, один ожидает, более старые
  пропускаются. Счётчик «Пропущено» отражает потерю, а не гарантирует полноту.
- Текст передаётся в DOM через `textContent` для предотвращения XSS.
- Экспорт TXT (двуязычный) и SRT (русский).
- Отдельное окно субтитров через локальный `BroadcastChannel`.

## Ограничения и безопасность
- **Это фразовый перевод, не синхронный дубляж.** Задержка >=6 секунд плюс
  распознавание и перевод на данном оборудовании. Нет гарантий точности.
- Не поддерживается захват звука из нативного desktop-приложения Толка
  там, где браузер/ОС не предоставляет аудиодорожку.
- Whisper может выдавать ложные фразы на шуме; проверяйте важные решения.
- Браузерный сборщик использует CDN и скачивает модели Hugging Face.
  Приложение **не отправляет аудио и расшифровку в API**, однако
  для закрытого корпоративного использования нужно самостоятельно
  закрепить/разместить зависимости в разрешённой инфраструктуре,
  проверить сетевые запросы и согласовать захват/перевод с организацией.
- Данные держатся в памяти текущей вкладки до очистки/закрытия;
  TXT/SRT сохраняются только по выбору пользователя.
- `AudioContext.createScriptProcessor` устаревший API; для следующего
  этапа планируется AudioWorklet и более строгая синхронизация таймкодов.
- Остаток <6 секунд при остановке обрабатывается (кроме хвоста короче 0,25 с);
  количество пропущенных фрагментов отображается.
- Звук, прозвучавший до подключения аудиоконвейера (первые доли секунды после
  выбора вкладки), не захватывается. Фиксированная граница 6 с может разрезать слово.
- Модели могут быть тяжёлыми на слабых ПК. Установите модели до совещания.

## Приёмка
- `node --check live-translate-core.js live-translate-worker.js live-translate.js`
  (по одному файлу) и `node live_translate_test.cjs`.
- Существующие тесты video/source/recording должны остаться зелёными.
- Ручная проверка **обязательна** на Windows + Chrome/Edge:
  Толк во вкладке, подтверждение аудиотрека, фактическая английская речь,
  русский результат, остановка/повтор, экспорт, отсутствие утечек.
- AI-модель, качество и задержка не считаются проверенными лишь по JS syntax/CI.

## Статус
Экспериментальная реализация в отдельной ветке на review.
Автоматический деплой запрещён, `main` не меняется.

## Проверка реальных моделей перед началом совещания (23.11.2026)

- Кнопка «Подготовить модели» сначала прогревает Whisper Tiny, затем загружает
  модель EN→RU. Теперь выполняется **реальный тестовый перевод** английской
  фразы, и только при наличии русского результата доступен «Начать перевод».
- Если основная конфигурация ONNX `q8` недоступна, пробуется резервная `q4`.
  Результат проверочной фразы и выбранный формат выводятся на экран.
- Подготовка ограничена 15 минутами. При зависании worker завершается и
  выводится диагностическое сообщение; разрешён повтор.
- `live_translate_browser_test.py` имитирует AI-модель и проверяет UI.
  Это **не подтверждает** работоспособность загрузки и вывода реального ONNX.
- Добавлен отдельный тест `live_model_real_test.py`, запускаемый вручную:
  `python live_model_real_test.py`; требуется Playwright, Chromium,
  доступ к Hugging Face и CDN. Аналогичный workflow
  `.github/workflows/speechlab-real-models.yml` запускается вручную
  через Actions / Run workflow. Он не запускается во время обычного CI.
- Результат реального теста пока **NOT VERIFIED**, пока не выполнен вручную
  на целевом устройстве или в отдельной среде. (Обновлено ниже: VERIFIED локально.)

## Глубокий аудит (23.11.2026, ветка `fix/speechlab-deep-audit-20261123`)

Исправлено:
- **Потеря фраз в переводе.** OPUS-MT переводил только первое предложение
  6-секундного фрагмента. Теперь перевод выполняется по предложениям
  (`SpeechLiveCore.splitSentences`). Подтверждено реальной моделью.
- **Зависание модели.** Сторожевой таймер (90 с без сообщений от Worker при
  фрагменте в обработке) освобождает Worker, завершает захват, считает потерю,
  разрешает повторную подготовку. Таймаут распознавания одного фрагмента — 45 с
  вместо 10 минут.
- **Необратимый отказ распознавания.** После исчерпания движков runtime
  отклонял все следующие фрагменты, а захват продолжался без результата.
  Теперь распознаватель пересоздаётся (WASM, кэш), после 3 ошибок подряд сессия
  останавливается с понятным сообщением.
- **Сбой Worker во время завершения** больше не ждёт 30 с.
- **Таймкоды** берутся из количества захваченных сэмплов (последний фрагмент
  заканчивается там, где заканчивается звук), а не из настенных часов.
- **Аннотации Whisper** (`[BLANK_AUDIO]`, `[Music]`, `(applause)`, `♪`) не
  переводятся как речь; из смешанного текста удаляются.
- Сообщение о недоступности моделей теперь указывает, что проверить.
