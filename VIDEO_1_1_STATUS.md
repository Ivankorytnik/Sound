# Видео 1.1: браузерная часть и ограничение выпуска

Дата аудита: 10.11.2026. База: `3b89676ade369ce69244f4cfe5fec1e2f3d066e2`.

## Результат аудита

В этом репозитории находятся статические HTML/CSS/JS, браузерный FFmpeg и существующий Whisper Worker. README указывает совместимость с GitHub Pages. Серверного приложения, очереди задач и конфигурации сервера здесь нет. Возможность выполнения FFmpeg CLI/yt-dlp на действующем хостинге не подтверждена; доступа к серверному окружению нет.

Архитектура существующих модулей и параметры Whisper не изменены. Дополнительных пакетов, платных сервисов и ресурсов не подключено. Это реализация браузерной части ТЗ, не полная готовность версии 1.1.

## Что реализовано

- Файл или прямая HTTP/HTTPS-ссылка, разрешённая CORS источника. На HTTPS-странице принимаются только HTTPS-ссылки.
- Проверка HEAD и ограниченным Range: до 1 МиБ начала и, при необходимости, до 1 МиБ конца MP4. Если Range проигнорирован, чтение прекращается на лимите. Браузер/сетевая буферизация может получить дополнительные байты; приложение не вычитывает весь большой файл при проверке.
- Название файла из URL; известный размер, формат. Для полного блока moov в MP4: длительность, разрешение, наличие звука. Если метаданные не получены, интерфейс указывает неопределённость.
- Один вариант качества для прямого файла: исходный. Нет списка выдуманных разрешений.
- Видео сохраняется из Blob/File с исходным контейнером и потоками, без перекодирования. MP4 не обещается для WebM/MKV. Отдельные потоки и манифесты HLS/DASH не поддерживаются.
- Локальные и полученные файлы: MP3/M4A, попытка копирования аудиопотока, затем конвертация при несовместимости; прослушивание.
- PCM для Whisper сохраняется до смены источника, повторная транскрибация использует отдельную копию буфера. Повторное действие не загружает видео заново.
- Отмена запросов через AbortController, FFmpeg/Whisper через terminate; устаревшие результаты игнорируются. Источник после успешного получения остаётся в памяти для повторных действий.
- Лимит 300 МиБ проверяется по доступным заголовкам и фактическим прочитанным байтам. 90 минут проверяются по доступным метаданным и декодированному аудио; декодирование ограничено 5401 секундой. Для скачивания исходного видео с неизвестной длительностью предел 90 минут до получения метаданных подтвердить нельзя.
- TXT содержит правки; SRT сохраняет автоматические сегменты. Об этом есть пояснение в интерфейсе.
- Обработка остаётся на устройстве. Исходный URL отправляется только источнику, без credentials и Referer. Запрос HEAD/Range может быть недоступен из-за CORS даже при доступности самого видео в браузере.

## Матрица источников на 10.11.2026

| Источник | Проверка / видео / аудио / Whisper | Статус проверки |
|---|---|---|
| Локальный MP4/AAC | Реализовано | Синтетические тесты; браузерная проверка через CI |
| Прямой MP4 с CORS | Реализовано | Контролируемые ответы тестового источника; доступность сторонних сайтов не проверена |
| Прямые WebM/MOV/MKV/AVI | Ограничено CORS, контейнером и сборкой FFmpeg | Нет подтверждённой проверки всех форматов |

| Закрытые записи / эфиры / плейлисты / DRM | Не поддерживается | Вне текущего объёма |

## Что требуется для полного ТЗ

Нужен аудит существующего сервера: тип хостинга, ОС, доступ к выполнению процессов/контейнеров, CPU/RAM, свободный диск, тарифы и квоты трафика. До этого серверный вариант не развёртывать.

Предлагаемый вариант без платных AI API: собственный обработчик с FFmpeg CLI и yt-dlp, одна очередь задач, анонимная сессия с защищённой cookie, привязка задач и скачивания к сессии, TTL для временных файлов вне публичной директории, отмена всего дерева процессов. Требуется сетевое ограничение исходящих соединений для самого обработчика, yt-dlp, FFmpeg и каждого вложенного запроса; одной проверки исходного URL недостаточно. Серверные требования SSRF, DNS rebinding, IPv6, редиректов, изоляции, rate limit, квот, очистки и доступа между пользователями из исходного ТЗ остаются обязательными и пока не реализованы.

Предварительный профиль для нагрузочного теста, не подтверждённая потребность: один процесс обработки, лимит входного медиа 300 МиБ, 90 минут, не менее 1 ГиБ квоты временного диска на задачу; отдельно измерить память и CPU при объединении и перекодировании. Диск ограничить общей квотой, срок хранения задать конфигурацией. Пример для 300 МиБ входного видео и такого же результата: около 600 МиБ суммарного входящего и исходящего трафика сервера без учёта повторов, метаданных и протокольных расходов. Итоговый бюджет зависит от хостинга и количества задач, дополнительные расходы сейчас не определены.

После подтверждения окружения реализовать обработчик и проверить каждую платформу на разрешённых тестовых роликах отдельно: метаданные, качество, скачивание видео со звуком, отдельное аудио, передача в существующий браузерный Whisper. Наличие extractor в yt-dlp не является доказательством поддержки.

## Проверка и выпуск

- `node --check video-source.js` / `node --check video.js`.
- `node video_source_test.cjs`: реальные синтетические MP4 с FFmpeg CLI; метаданные, URL, лимит заголовка, ограничение чтения Range, отсутствие cookies/Referer, отмена.
- `python video_url_test.py`: контролируемые HTTP-ответы через Playwright; прямое скачивание и побайтовая проверка, кэш, метаданные, отсутствие звука, ошибки, отмена и мобильная ширина. Это не проверка доступности реального стороннего CDN.
- `python video_e2e_test.py`: настоящий ffmpeg.wasm, проверка MP3/M4A через ffprobe, повторное использование PCM, TXT/SRT. ASR в этом тесте подменён: качество реального Whisper этим тестом не подтверждается.
- Существующие `smoke_test.py`, `video_smoke_test.py`: регрессия основных режимов и локального выбора файла.
- Браузерные тесты в локальном окружении заблокированы запуском Chromium; необходимо получить результаты GitHub Actions до выпуска.

Изменённые файлы: `video.html`, `video.css`, `video.js`, `.github/workflows/speechlab-smoke.yml`, `video_e2e_test.py`. Добавлены `video-source.js`, `video_source_test.cjs`, `video_url_test.py`, этот отчёт.
